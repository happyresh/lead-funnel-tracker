# House Style and Voice

**Status:** Control

How every document, comment and user-facing text in this project is written.

## 1. Hard Bans

- No em dashes; use a comma, colon, period or parentheses instead.
- No emojis in code, comments, commits or documents.
- No hype words: revolutionary, seamless, cutting-edge, game-changing, robust (without specifics), leverage (as a verb).
- No claims without evidence: never say a feature is complete because a screen, TODO or schema exists; never say "production-ready", "secure" or "deployed" without proof.
- No "prototype", "mock" or "demo" in user-facing text.

## 2. Register by Document Type

| Document type | How to write |
|---|---|
| Engineering docs (build guide, SAD, QAD) | Direct and testable; label items Implemented, Verified, Planned, Deferred or Blocked |
| Requirements (PRD, IDEA) | Plain statements of need; one rule per sentence |
| Academic or client documents | Formal but plain; consistent project name and terms |
| User interface text | Everyday words; truthful empty, error and unavailable states |
| Security statements | Name the control or test; never a bare "secure" |
| Code comments | One sentence, explains why, not what |

## 3. AI-tell Pass (before finishing any document)

Remove:
- exaggerated certainty and filler adjectives;
- fake precision and numbers without a source;
- lists of three used only for rhythm;
- opening or closing summaries that repeat the section;
- stacked hedging that says nothing.

Then read it aloud once.
